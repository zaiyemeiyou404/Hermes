# 通过任务 ID 回忆对话

## 原理

task-pulse 的任务 ID（如 `task_1779708691142_1`）在以下位置出现，可被 `session_search` 检索：
- 创建任务时 API 返回的 JSON 响应
- `.task-pulse-data/` 目录下的任务 JSON 文件
- 会话日志中 Hermes 对任务的引用（"已创建 task_xxx" 等）

## 使用方式

**格式：** 直接提供任务 ID，最好附带一句任务标题或描述。

```
✅ 好的用法：task_1779708691142_1，这个是我让你备份Hermes的
✅ 好的用法：task_1779708691142_1，当初让你创建agent仓库那份
❌ 差的用法：task_1779708691142_1
```

## 准确率参考

| 条件 | 预期准确率 |
|------|-----------|
| 任务在本会话中创建 + 附带描述 | ~90% |
| 任务在历史会话中 + 附带描述 | ~70-80% |
| 仅 ID 无描述 | ~30-50% |

## 局限性

- `session_search` 基于文本关键词匹配，不是数据库精确查询
- 如果任务创建后从未在对话中被提及（比如 demo runner 自动创建），ID 不会出现在任何会话文本中 → 无法搜到
- 搜索范围有限（不是无限上下文回溯）

## 最佳实践

1. 创建任务时在 prompt 字段写清楚详细描述 → 日后搜索时更易命中
2. 需要回忆时，提供 ID + 一句描述 → 准确率最高
3. 如果某任务日后可能需要回顾，在创建时告知 Hermes 记录关键上下文
